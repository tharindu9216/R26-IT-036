# C1 Feature-MLP live inference

This package runs the exported C1 BVP/EDA Feature-MLP entirely from local
artifacts. Its runtime timeline is fixed to the research manifest:

```text
0-300 s    personal calibration (49 overlapping 60 s windows)
300-360 s  fresh post-calibration sensor window
360 s+     calibrated stress prediction every 5 s
```

## Compatible firmware

Flash `iot/c1_stress_detection_bvp/streamlit_serial/streamlit_serial.ino`.
It emits raw samples at 230400 baud:

```text
DATA,<millis>,<MAX30102_IR>,<GSR_ADC>
```

The Firestore firmware is not an inference input. It uploads already-aggregated
values every five seconds, while this model must receive the raw stream to
reconstruct each 60-second feature window.

## Install

```bash
python -m pip install -r backend/c1/requirements.txt
```

The scikit-learn range is intentional: the exported imputer, scaler and
isotonic calibrator were saved with scikit-learn 1.6.1.

## Background service

```python
from c1 import C1ServiceConfig, SerialSensorService


def receive_prediction(result):
    print(result.label, result.calibrated_probability)


service = SerialSensorService(
    C1ServiceConfig(port="/dev/ttyUSB0"),
    on_prediction=receive_prediction,
)
service.start()

# Keep `service` alive for the lifetime of the application.
# Read service.snapshot() for calibration/warm-up progress.
# Call service.stop() during application shutdown.
```

Use `service.restart_calibration()` whenever the device restarts, the wearable
is moved to a different user, or sensor contact changes materially.

## Testing without a wearable

`replay.py` lets a recorded firmware capture stand in for a live serial port,
via `SerialSensorService`'s `serial_factory` hook, so nothing else about the
service changes:

```python
from c1 import C1ServiceConfig, ReplaySerialConnection, SerialSensorService, parse_recording

lines = parse_recording(open("sample_recording.txt", "rb").read())
service = SerialSensorService(
    C1ServiceConfig(port="replay:sample_recording.txt"),
    serial_factory=lambda **_: ReplaySerialConnection(lines),
)
service.start()
```

The recording is replayed at the pace implied by each line's own `millis`
field (default `speed=1.0`, i.e. real time), so calibration + warm-up still
take the full ~6 minutes and predictions still arrive every 5 seconds — the
timeline is identical to a live sensor, it just doesn't require wearing the
device for every test run. `api.py`'s `POST /api/sensor/upload` and
`supportive_app.py`'s sensor gate both use this.

`sample_recording.txt` (400 s, generated by `make_sample_recording.py`) is a
ready-made synthetic capture for trying this out immediately:

```bash
python backend/c1/make_sample_recording.py backend/c1/sample_recording.txt --duration 400
```

### Real Empatica E4 / WESAD sessions

`e4.py`'s `convert_e4_to_firmware_lines(bvp_raw, eda_raw)` converts a real
E4/WESAD session's `BVP.csv` (native 64 Hz) + `EDA.csv` (native 4 Hz) into the
same `DATA,...` line format, upsampling EDA onto BVP's timestamp grid via
linear interpolation. `api.py`'s `POST /api/sensor/upload` and the Streamlit
gate both accept a `BVP.csv` + `EDA.csv` pair directly (matched by filename;
`TEMP.csv`, `HR.csv`, `IBI.csv`, `ACC.csv`, `tags.csv`, `info.txt` are ignored
— C1 only consumes BVP + EDA).

Caveat: `inference.py`'s `median_ir < 20000` "weak signal" check is tuned to
the ESP32's raw MAX30102 ADC scale. E4's BVP units are a different, smaller
scale, so calibration may raise `SignalQualityError` on genuine E4 data even
when the signal is fine — that threshold has not been made source-aware yet.

## Inference sequence

The probability path is:

```text
18 raw features
-> personal feature z-score
-> SimpleImputer
-> StandardScaler
-> Feature-MLP sigmoid
-> Feature-MLP IsotonicRegression
-> threshold 0.295
```

`C1Prediction.raw_probability` is the sigmoid output. The application should
use `calibrated_probability` and `is_stressed` for routing.

## Security

Do not commit real Wi-Fi passwords or Firebase credentials in firmware. Store
them in an ignored secrets header or provision them at deployment time.
